## 诊断「点击继续游戏无反应」（用户附 godot.log）

- 结论：**不是 ManosabaLin 的问题**，崩在 **BaseLib v3.4.7**（Workshop 3737335127）。
- 整份日志唯一的 ERROR：`System.NullReferenceException`
  → `BaseLib.Abstracts.CustomMessageWrapper.Unregister(INetGameService)`
  ← `BaseLib.Patches.Networking.RunManagerPatches.DisposeCustomMessageHandlers`（对 `RunManager.CleanUp` 的 `[HarmonyPostfix]`）
  ← `RunManager.CleanUp_Patch2`
  ← `NMainMenu.OnContinueButtonPressedAsync()`。
- 机制：`RunManager.CleanUp` 首行 `if (State == null) return;`，主菜单下 `State` 为 null，
  `NetService` 从未初始化 → BaseLib 空检查缺失 → NRE。
  因为 NRE 是在 `NMainMenu.cs:717` 的 **catch 块内**抛的，`throw;` 与 `DisplaySaveError()` 都不执行
  → 原始异常被顶掉、不弹错误框、按钮停在禁用态 → 表现为「只有继续游戏点不动」。
- 佐证：日志无 `Continuing run with character:`；`current_run.save` 失败后未被重写
  → 失败点在 `RunState.FromSerializable`（NMainMenu.cs:706）而非 707 的 `SetUpSavedSingleplayer`。

## 更新（第二份 godot.log）：真正的阻塞点找到了

- mod 组合变了（Loaded Mods 16 → 14；ManosabaLin/MinionLib/RitsuLib 现在走 Workshop 版），
  BaseLib 的 NRE 不再出现，于是**原始异常暴露出来**：
  `System.ArgumentNullException: Value cannot be null. (Parameter 'source')`
  → `System.Linq.Enumerable.Select` ← `MegaCrit.Sts2.Core.Rooms.RoomSet.FromSave`
  ← `ActModel.FromSave` ← `RunState.FromSerializable_Patch2` ← `NMainMenu.OnContinueButtonPressedAsync`。
- **根因：存档 act[3] = `ACT.HOUSE_OF_SPIDERS_RYOSHU_ACT_SPIDER_NEST_ACT`（HouseOfSpidersRyoshu 0.0.120-dev）
  的 `rooms` 里 `elite_encounter_ids` / `event_ids` / `normal_encounter_ids` 都是 null**，
  而 `RoomSet.FromSave`（`RoomSet.cs:144`）对这三个列表裸调 `.Select()`。
  该 act 的 `saved_map` 是手写 3 节点图（ancient→shop→rest→boss），列表本来就该为空，
  mod 没填 `Rooms` 的列表 → 存盘写 null → 读档必炸。
- 判据：act[0..2] 三个列表齐全（15/32/15 等），只有 act[3] 三个键**完全缺失**；
  而 `second_boss_id` 被显式写成 `null` → 序列化器写 null 字符串、不写 null 集合，故内存里就是 null。
- **修复已执行**：对 `current_run.save` + `.backup` 行级插入三个 `[]`（保 UTF-8 无 BOM、纯 CRLF）。
  261824 → 261923 B（+99）。备份在 `.local/backup/save-repair-20260921/`。
- 报告：`.local/reports/continue-game-dead-button.md`。

### 复用要点

- `RunState.FromSerializable` 内部顺序是 **先 players 后 acts**，所以异常来自 `Player.FromSerializable`
  还是 `save.Acts.Select(ActModel.FromSave)` 可以直接由栈判断（`parameter 'source'` = LINQ 收到 null 集合）。
- 读档失败的定位手法：用 `Get-Item` 看 `current_run.save` 的 mtime 有没有被改写
  （`SetUpSavedSingleplayer` 里的 `IncrementNumReloads` 会写档）；
  没改写 ⇒ 炸在 `RunState.FromSerializable`，还没到写档那步。
- 存档 JSON 是 2 空格缩进 + CRLF + **无 BOM**；改档要用
  `ReadAllText` → 字符串替换 → `UTF8Encoding($false)` 写回，绝不要 `ConvertTo-Json` 往返
  （会重排/重转义整个文件）。

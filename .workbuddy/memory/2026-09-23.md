### 技术侦察结论（下次实现可直接复用，已核实到源码）

- **死亡拦截不需要 Harmony**。`PowerModel` 覆写 `ShouldDie(Creature)` 返回 `false` 即可拦截；
  引擎随后只对该 preventer 调 `AfterPreventingDeath(Creature)`（在里面 `CreatureCmd.Heal` 即可）。
  调用链：`CreatureCmd.KillWithoutCheckingWinCondition`
  → `Hook.ShouldDie(runState, combatState, creature, out preventer)`
  → `Hook.AfterPreventingDeath(runState, combatState, preventer, creature)`
  → 若 `creature.IsDead` 仍为真则 `recursion + 1` 递归重杀。
  先例：原生遗物（用 `ShouldDieLate` + `AfterPreventingDeath`，`HealVar` 50%）、
  `MockPreventDeathPower`（用 `ShouldDie`）。
  ⇒ 「不死」可纯 Power 实现，**零 Harmony**。
- **「打出后本回合立即结束」有原生先例**：`VoidForm.OnPlay` 末尾直调
  `PlayerCmd.EndTurn(base.Owner, canBackOut: false)`（签名 `public static void EndTurn(Player, bool, Func<Task>?)`）。
- `TargetType.AllEnemies` 存在；伤害用
  `CreatureCmd.Damage(choiceContext, target, amount, props, dealer, cardSource, cardPlay)`。
  自杀伤害先例：`ValueProp.Unblockable | ValueProp.Unpowered`。
- **远古事件（Ancient）落点不明 ⇒ 别用**。mod 里唯一现存的 `WitchoftheIsland`
  注册在 `DeprecatedAct`，而该幕 `AllAncients` / `AllEvents` 全是空数组、
  `NumberOfWeakEncounters = 0`、`BaseNumberOfRooms = 0` ⇒ **不会自然出现**；
  RitsuLib 的 `AppendActAncients` 是追加合并，同幕再挂一个会变成随机二选一。
  且远古事件强制要 `.tscn` 背景 + 地图图标 + 历史图标（美术资源）。
  ⇒ **「火之时代」改走普通事件**：`ModEventTemplate` +
  `[RegisterActEvent(typeof(Hive|Overgrowth|Glory))]`；`ModEventTemplate.AssetProfile`
  默认 `EventAssetProfile.Empty`，**不需要任何美术资源**。普通事件现成先例：
  `TeamCardExchangeEvent`（Hive）、`MultiplayerCooperationEvent`（Overgrowth）、
  `KinmaneyurakuchoEvent`（Glory）。
- `ManosabaPowerTemplate` / `ManosabaRelicTemplate` 的图标都会回落到 `power.png` / `relic.png`，
  新卡/新能力/新遗物**不需要美术**。
- 其余先例：`RemoveOnPlayComponent`（在 `ManosabaLin.Characters.Sherrylin.Components`）、
  `CardCmd.Exhaust(choiceContext, card, skipVisuals)`、`CardPileCmd.RemoveFromCombat`。

### 两个必须先解决的设计矛盾（已抛给用户）

- **爆裂魔法与烬火洗礼同构**：烬火洗礼已经是「消耗目标全部火色 → 层数×3 打全体」（2 费 Rare）。
  爆裂草案只是费用 +1、倍率 +2、消耗对象从单个变全体 ⇒ 新鲜度不足，需要另给独有的一环。
- **余火体系里「烧牌」是收益而非代价**（痛觉的重量→力量、你的包容很刺眼→伤害+格挡、
  灰烬的余温→格挡、第二次点燃→把烧掉的牌捞回手牌、隔着火的玻璃→回手），
  所以「烧掉所有带余火的牌」读起来是**最大化引擎**而不是「自爆」；要成立必须补真代价。

### 「嫌疑」与「魔女化」的实际机制（用户把「罪与罚」改挂到这两个体系，故需精读）

- **嫌疑 = `SuspectPower`**（在 `Characters/Hiro/Powers/`，但全角色共用）
  - 每累计 **2 层 → 持有者 −1 力量**；满 **12 层** → 给持有者手牌生成「坏结局」诅咒卡
    （挂敌人则是清空其全部增益、回合结束后归还）
  - 亚里沙的用法：`YalisalinSuspectSpread` 自身嫌疑**每层 +1 伤害**，给自己和目标各 1 层
  - ⚠️ **已知缺口**：`GiveBadEndingCurse` 只认 Emalin / Ananlin / Sherrylin，
    其余角色（含**亚里沙**）一律落到 `HiroBadEnding` ⇒ 她会拿到**广野宏的**坏结局诅咒卡。
    要做「罪与罚」建议先补一张亚里沙专属坏结局诅咒。
- **魔女化 = `WithPower`**（同样在 `Characters/Hiro/Powers/`，全角色共用）
  - **它不只是惩罚，它是伤害增益**：`ModifyDamageMultiplicative` = `1 + Amount/200`，
    `ModifyDamageAdditive` = `Amount/50` ⇒ **200 层 = ×2 伤害**
  - ≥200：每打出 1 张技能/能力牌失去 1 生命；每回合结束失去 13 生命
  - ≥300：技能牌打出后进消耗堆；攻击牌打出后回复 3 生命
  - **满 100 时给亚里沙一张专属卡 `Ignite`（点火）**，并由
    `YalisalinsHairpin.IsCarbonizationUnlocked`（`WithPower.Amount >= 100`）解锁**炭化（黑红火色）**
  - 惩罚可被 `Powerthreethree` 能力豁免（`ShouldIgnoreWitchificationHpLoss`）
- 推论：**嫌疑 = 廉价但折力量的伤害加值；魔女化 = 昂贵但乘算的伤害加值**。
  两者都是"危险计数器 → 伤害"的转换器，因此「罪与罚」的合理形态是**把嫌疑倒进魔女化**。

### 「火之时代」设计（本轮给出方案，待用户拍板）

⇒ **连带要改「火之时代」的发放方式**：结局卡必须**永久加入卡组**（而不是加入手牌后一次性），

> **火之时代**（1 费 能力 先古）：打出时从【传火】【灭火】【夺火】中**选 1 张永久加入卡组**（本局）。

【薪柴】每层使你在**每场战斗开始时获得 1 点力量**。
⇒ 收益不再是固定值，而是**玩家自己拧的旋钮**（投入越多换越多），根除「收益太低」。
兑换率参照：等于「用 5 点最大生命买一件 Vajra（每场开局 +1 力量）」。

**夺火 v7**（攻击 · 全体 · 先古 · Lin 池 · 不消耗）：
对全体 6 点伤害 + 获得 1 层【独占】；目标有增益则夺取其全部增益据为己有并额外 +1 层；

⇒ 与传火刻意对称：**传火 = 我越来越强（代价是最大生命）；夺火 = 敌人越来越弱（无硬代价，

待定：是否补代价（最贴意境的是「每层【独占】使你每场战斗开始失去 1 点生命 —— 火不再温暖你」）。

**灭火保持**（用户已认可）：它是**一次性改规则的能力牌**，与「可重复的成长牌」不冲突 ——

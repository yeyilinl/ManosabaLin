### 关键结论：`Forgive()` 本身不依赖牌在哪个堆

- `Originalsin.Forgive()`（`Originalsin.cs:142`）只做「加计数 Power + 跑卡自身 Forgive 分支 + 广播 `ForgiveTriggered`」，
  **没有** `Pile` 前置判断；唯一的手牌判断在 `AfterPlayerTurnStartEarlyPostfix`（`Card.Pile?.Type != PileType.Hand` → return），
  那是「回合开始自动宽恕手牌原罪」的另一条通路，与 `Forgive()` 无关。
- 部分 Forgive 分支会搬这张牌本身（`ForgiveAnanlinVanity` / `ForgiveCocoworry` → `CardPileCmd.Add(card, PileType.Draw, Random)`；
  `ForgiveMiliaLost` → `RemoveFromCombat` + `GiveToAnotherPlayer`）。
  **已验证 `CardPileCmd.Add` 对「目标堆 == 当前堆」是安全的**：先 `card.RemoveFromCurrentPile()` 再
  `AddInternal(card, Random → NextInt(cardPile.Cards.Count + 1))`，取的是**移除后**的计数，只会重排位置，不抛异常。
  `RemoveFromCombat` 只在牌不属于任何战斗牌堆时抛（`CardPileCmd.cs:126`），抽/手/弃都算战斗牌堆。
- `SamePlaceTruth.IsSelectionLocked` 只会对「弃牌堆里锁定中的旧识疑影」为真，而旧识疑影**没有 `Originalsin` 组件**，
  所以「所有牌里的原罪」不可能命中锁定卡——这两处新代码**没加** `IsSelectionLocked` 过滤是刻意的，不是漏了。

2. `YalisalinFireComponentResolver.BuildDefaultConnectionPool`（余火用）
3. `ShuangGuiRiPower.CollectForgivableCards`（原罪，private static）

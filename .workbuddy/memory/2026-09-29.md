## 00:40 「看不见遗物」排查 → 用户裁定：获取渠道跟随海克斯，我们不做

用户问「怎么我看不见遗物」。查清了**根因（不是显示 bug）**：

`RelicGrabBag.Populate`（`MegaCrit.Sts2.Core.Runs/RelicGrabBag.cs:63-68`）：
```csharp
list = ModelDb.RelicPool<SharedRelicPool>().GetUnlockedRelics(...).ToList();  // 只认**原版** SharedRelicPool
list.AddRange(player.Character.RelicPool.GetUnlockedRelics(...));              // + 当前角色池
list.RemoveAll(r => !_rarities.Contains(r.Rarity));                            // _rarities = Common/Uncommon/Rare/Shop
```
- 抓取袋**只有两个来源**：原版 `SharedRelicPool` + 当前角色的 `RelicPool` ⇒ **`LinRelicPool` 不在其中**
  （RitsuLib 的 `AppendSharedRelicPools` 只补 `ModelDb.AllSharedRelicPools`，抓取袋这里没读它）；
- 再加上 `RemoveAll` 直接丢掉非 Common/Uncommon/Rare/Shop ⇒ **`Starter` 必被丢**；
- `RelicFactory.RollRarity` 也只掷 Common/Uncommon/Rare。
- 附带：`RelicModel.cs:197` 的 `IsTradable` 对 Starter/Event/Ancient 返回 false（另一条「不属于奖励流」的证据）。
- 补充：本项目**既有遗物也都是 Starter**（`YalisalinsHairpin`/`MagnifyingGlass`…），它们靠**事件**或
  `AnanTestConsoleCommand` 的 `RelicCmd.Obtain<T>` 发放 —— 同一个套路。

⭐ **用户裁定**：「保持 Starter，走专项发放」→「**跟随海克斯啊，不用你管**」
⇒ **不要**给这 6 个遗物自建任何获取渠道（起始遗物 / 自定义 reward / 事件都不做），
获取完全交给海克斯符文系统；我方离线身份只保证「没装海克斯也不报错」。

已把这个结论写进 `docs/hextech-compat-ours.md §2.8`（含那段 `RelicGrabBag` 源码 + 「不要改 Rarity」的警告）。

## 花朵绽放的引擎接法（本轮最重要的新知识）

- 引擎**没有**变形/生成的前置替换钩子（RitsuLib 的 `ModCardTransformRegistry` 只能事后通知）。
  → 自写 Harmony **前缀**：用 `ref Task<...> __result` 赋自己的 Task 并 **`return false`** 跳过原方法；
  前缀不能 await，真正的玩家选择在返回的 Task 里 await。补丁内部再调原命令时用静态
  `Intercepting` 标志放行（否则无限递归）。
- 两个拦截点：
  - `CardCmd.Transform(IEnumerable<CardTransformation>, Rng?, CardPreviewStyle)` —— 四个重载都汇流到这里；
  - `CardPileCmd.AddGeneratedCardsToCombat`（`AddGeneratedCardToCombat` 会委托给它）。
- **拿不到 `PlayerChoiceContext`**：`CardCmd.Transform` 根本没有这个参数，而 `ThrowingPlayerChoiceContext`
  会在 `SignalPlayerChoiceBegun` 直接抛 `NotImplementedException`，不能拿来弹界面。
  解法：Harmony 挂 **`CardModel.OnPlayWrapper`**（前缀存 context、后缀把返回的 Task 包一层，
  在完成时还原上一份值），这样卡牌结算期间就能取到正确的、可暂停动作队列的上下文。
- `CardTransformation` 是 **readonly struct**；`new CardTransformation(original, replacement)` 可在拦截时改替换目标。
- 热路径补丁必须廉价：先用静态 `FlowerBloomTracker.Any`（活跃能力列表是否非空）做前置短路。
- **生成拦截只在 `CardPlayContext.Current != null` 时生效**（避免回合开始/遗物发牌等时机弹选择屏把流程打断）。
- 组件方法 `AddComponent` / `GetComponent` 定义在 **`ComponentsCardModel`**（`MinionLib.Component`）上，
  不在 `CardModel` 上 —— 必须先 `is ComponentsCardModel` 再调。

## 收尾时查出的两个真 bug（已修 + 已重发）

1. **可点击能力用完就被引擎删掉，「每回合补充」永远不会发生。**
   `PowerCmd.Decrement` → `ModifyAmount` 末尾有
   `if (power.ShouldRemoveDueToAmount()) await Remove(power);`，
   而 `PowerModel.ShouldRemoveDueToAmount()` 在 `Amount <= 0 && !AllowNegative` 时返回 **true**。
   所以 `DecrementAfterAct => true` + `StackType.Counter` 的能力，用一次（1→0）就整个消失了，
   `AfterPlayerTurnStart` 里的补充逻辑根本没机会跑。
   → `IAmCorrectAction` 改成 **`DecrementAfterAct => false`**：层数恒为 1，
   用回合内私有标记 `_usedThisTurn` + 覆写 `ActionModel.CanAct` 来限次，自己回合开始时清标记。
2. **「回合开始消失」不能对所有玩家生效。**
   `FalselyAccusedPower` 原来的 `AfterPlayerTurnStart` 对**任何**玩家的回合开始都 `RemoveInternal()`。
   多人局里 `被伪证` 会在下一个队友回合开始时立刻消失，
   **根本撑不到敌人回合**（怪物就是在敌人回合打人）→ 效果整个作废。
   → 加守卫 `if (player?.Creature != Owner) return;`，只在**持有者自己**的回合开始移除。

**这两个坑都会在「代码编译通过、静态看不出问题」的情况下静默失效，值得单独记住。**
跑 `RunSts2Tests`（5/5 通过）只能证明补丁能正常加载，证明不了这类时序逻辑 —— 仍需人工推演。
